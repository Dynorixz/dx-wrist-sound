# Проверка DX • Wrist Sound 1.2.0

7 октября 2026 года. Предыдущая проверка сохранена в VERIFICATION-1.1.1.md.

## Сборка и проверка

`tools/build-local.ps1` теперь по умолчанию выполняет:

```text
gradlew :mobile:assembleRelease :wear:assembleRelease :shared:testDebugUnitTest lintRelease
```

Последняя сборка: **BUILD SUCCESSFUL**, 3 минуты 14 секунд. APK — release с R8 и resource shrinking, debuggable=false. Package `dev.dx.wristsound`, versionCode=4, versionName=1.2.0, minSdk=30, targetSdk=36, compileSdk=37.2. `aapt2 dump badging` подтвердил метаданные и REQUEST_IGNORE_BATTERY_OPTIMIZATIONS / SYSTEM_ALERT_WINDOW в APK часов.

Все **35 unit tests** прошли: failures=0, errors=0. AutomationTest — 10, RegressionTest — 12, ScreenLockRegressionTest — 8, MonitoringRecoveryTest — 5. Новые тесты проверяют повторную подписку после ошибки регистрации и нормального завершения, отмену во время ожидания повтора, освобождение CPU lease при ошибке обработки и распространение downstream exception без бесконечного повторения. Это не аппаратная эмуляция сна, PIN или окон Wear OS.

| Модуль | Ошибки Lint | Предупреждения |
|---|---:|---:|
| mobile | 0 | 8 |
| wear | 0 | 4 |
| shared | 0 | 1 |

Отчёты находятся в `*/build/reports/lint-results-release.html` и `shared/build/reports/tests/testDebugUnitTest/index.html`. Предупреждения: более свежие зависимости/targetSdk, DataExtractionRules для API 30, статичные русские строки native popup, пустой super.onCleared и BatteryLife для системного запроса исключения из оптимизации. Запрос нужен для пользовательского постоянного мониторинга и фонового восстановления службы, выдаётся пользователем вручную. Lint также вывел два сообщения XML parser `Content is not allowed in prolog`; итоговые XML/SARIF отчёты не содержат ошибок. Эти сообщения не выдаются за проверку отображения UI.

## Установка и проверка на устройствах

Во время первоначальной сборки физические устройства были недоступны. При последующей установке обнаружены Xiaomi 25113PN0EG (192.168.31.239:37671) и Samsung SM_L355F (192.168.31.248:33209), оба ранее имели 1.1.1. Обновление выполняется через adb install -r с сохранением данных.

После первой установки на реальных устройствах выявлено удаление `@array/android_wear_capabilities` ресурсным оптимизатором: физический Node был рядом, но capability отсутствовала, поэтому сообщения не принимались. Добавлены отдельные tools:keep XML в оба модуля. Сборка теперь проверяет массив и его значение в готовом APK. Финальная сборка прошла обе проверки; aapt2 подтвердил dx_wrist_phone и dx_wrist_watch. На часах также исправлен верхний отступ: заголовок больше не должен перекрывать системное время.

Исправленный APK телефона установлен и открыт. SHA-256 установленного base.apk равен 36EE60E058621D50742642778B1014E48FE1EE73D8BAC561151A71108454AB52, что соответствует финальному APK. Обе финальные копии загружены в /sdcard/Projects телефона и проверены SHA-256.

После пробуждения часов финальный APK успешно установлен через adb install -r по адресу 192.168.31.248:33209 и открыт. Package manager подтвердил versionCode=4 и versionName=1.2.0. SHA-256 установленного base.apk равен 7AA28F4C1808B2862EF2E95F7C010D36F6C322FFC99CC2DBD327383929A2D73A, что соответствует финальному APK часов. Установка обоих исправленных APK завершена с сохранением данных.

Реальная доставка сообщений подтверждена на телефоне: журнал 7 октября в 21:42:45 показывает `Watch connected: Galaxy Watch9 (B1GL)`, в 21:42:57 — `Watch ON_WRIST confirmed` и `Phone ring volume -> 0/15, mode=0`. В 21:45:15 и 21:45:18 поступили новые UNKNOWN и ON_WRIST. Снимок `artifacts/qa-1.2.0/phone-final.png` показывает «Часы на руке», обновление 21:44:24, включённую автоматизацию и громкость 0/15. Foreground служба телефона подтверждена dumpsys: isForeground=true, foregroundId=10, connectedDevice.

Первоначальная 1.2.0 на часах подтвердила наличие wake-up offbody датчика и foreground службы. Финальный APK передаёт актуальные состояния на телефон. Беспроводная отладка часов снова отключилась после установки: финальный screencap получился чёрным из-за спящего экрана, поэтому он не подтверждает исправленный отступ заголовка. Новое меню часов после изменения отступа, popup и звук ещё требуют визуальной проверки на активном экране.

При последней успешной проверке на часах SYSTEM_ALERT_WINDOW имел default mode, пакет отсутствовал в battery optimization whitelist. Пользователю нужно вручную разрешить окно над циферблатом и работу ночью, если эти доступы ещё не выданы. Системные разрешения через ADB не выдавались.

Создан отдельный Wear OS API 36 small round AVD DX_Wrist_120_QA (384×384). Emulator `-accel-check` сообщил, что аппаратный hypervisor driver не установлен. Две попытки headless запуска не дали готового ADB устройства; UI, popup, звук, FPS и recovery через Android runtime на этом эмуляторе не подтверждены. Эмулятор не используется как доказательство ночного сценария. Процессы проверки остановлены, созданный для неё AVD удалён.

Дополнительно `apkanalyzer manifest debuggable` вернул false для обоих APK, а `aapt2 dump resources` подтвердил включение raw/phone_loss_chime. Проверка CRC source ZIP успешна; исходники recovery и мелодия включены, локальные ключи исключены.

На физических часах необходимо разрешить **Работа ночью** и **Окно поверх циферблата**, уведомления и слышимую громкость медиа. Для русского голоса нужен офлайн-голос TTS. Проверить:

1. Работа до утра с закрытой Activity, снятие/надевание без запуска приложения.
2. Восстановление после завершения процесса системой, после reboot с включённым автозапуском и после обновления.
3. Окно поверх циферблата, кнопка «Понятно», закрытие при reconnect и через 30 секунд; режимы мелодии и речи.
4. Отсутствие тревоги на краткий disconnect, UNKNOWN и OFF_WRIST; один сигнал на эпизод.
5. Выбор на часах при отсутствии связи, его доставка на телефон при reconnect и ACK.
6. Прокрутка release UI и фактическое время кадра на реальных часах при разных режимах питания.

Inexact alarm назначается примерно через 15 минут и может задерживаться прошивкой. Без исключения из оптимизации Android может запретить старт FGS из фона. Force stop отменяет фоновые запуски до ручного открытия. Запрос preferredRefreshRate=60f не гарантирует 60 FPS. Non-wake-up сенсор по-прежнему не может сам разбудить CPU до callback.
