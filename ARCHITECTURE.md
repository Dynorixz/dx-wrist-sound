# DX • Wrist Sound — архитектура

## Модули

- `shared`: модели, двоичный протокол v1, чистая state machine, debounce, DataStore и ограниченный журнал.
- `wear`: SensorManager → WristDetectionProvider → debounce → MessageClient; Wear Compose Material 3 UI и сервис наблюдения.
- `mobile`: WearableListenerService / callback → WristStateRepository → SoundModeController; Compose Material 3 UI, настройки и диагностика.

## Состояние и доставка

`UNKNOWN` не означает снятые часы. Подключение отдельно от состояния запястья. Выбирается стандартный off-body wake-up sensor, затем стандартный non-wake-up вариант. Без него провайдер выдаёт UNKNOWN: пульс, движение, блокировка экрана и Bluetooth не подменяют факт ношения.

На часах входной поток проходит независимый debounce: 3 s для надевания, 5 s для снятия по умолчанию. MessageClient доставляет подтверждённые snapshots по `/wrist_state`; каждые 2 минуты отправляется snapshot по `/heartbeat`. UUID сессии и sequence защищают от повторов. После reboot состояние не считается актуальным до нового события датчика. Формат snapshot остаётся v1, настройки расширены до v2 с чтением предыдущей версии.

С 1.1.1 sensor callback синхронно приобретает ограниченный CPU wake lease до передачи `WristReading` в Flow. Владение переносится через debounce до завершения `repository.confirmed`/publish и освобождается в finally. На bounce сначала приобретается новое владение, затем освобождается прежнее; output debounce намеренно не отбрасывает возврат к уже подтверждённому состоянию, поскольку ему требуется cleanup. Сервис в таком случае не применяет звук повторно. Отмена подписки освобождает её собственное pending владение. Android PARTIAL_WAKE_LOCK не держит экран и не меняет Keyguard; acquire(timeout=75000) ограничивает утечку при зависании. Non-wake-up датчик не начинает будить CPU от добавления lock внутри callback.

Ошибка запроса Data Layer не доказывает disconnect. Capability сопоставляется с локальными NodeClient nodes. На телефоне перед disconnect fallback проверяется наличие выбранных часов; перед heartbeat fallback отправляется запрос snapshot с единственным окном 30 s. Аналогичная проверка реализована в резервном AlarmManager, если основной процесс исчез.

## Предупреждение о потере телефона

Wear FGS содержит PhoneLossMonitor с отдельной чистой PhoneLossPolicy. Тревога требует предыдущего подключения, ON_WRIST, непрерывной потери 30 s и успешной повторной проверки отсутствия локального телефона. API errors откладывают проверку, а не запускают тревогу. На эпизод допускается один баннер/голос; rearm после 60 s устойчивого reconnect. UNKNOWN/OFF_WRIST не запускают тревогу. При reconnect незавершённая речь и уведомление отменяются.

Баннер использует high-importance Wear notification с оригинальной vector-иллюстрацией lost_phone, без overlay/full-screen permission. OfflineSpeech лениво создаёт TextToSpeech, выбирает установленный русский голос без network requirement, получает краткий audio focus и освобождает движок. Громкость медиа и DND не изменяются.

Общий PermissionGuide описывает реальные доступы и публичные Settings intents с fallback. AppLinks хранит три ссылки dynorixz в общих ресурсах. На часах явное нажатие отправляет /author_link; телефон принимает только разрешённые URL от проверенного локального узла и показывает notification с PendingIntent. Браузер открывается только по нажатию пользователя.

Для локального режима отправка и приём разрешены только для `Node.isNearby`. DataClient намеренно не используется: сохраняемый/отложенный ON_WRIST не должен выключать звук после восстановления связи. DataStore хранит настройки и журнал на каждом устройстве; сервер приложения отсутствует.

## Применение звука

State machine имеет DISABLED, UNKNOWN, WATCH_ON_WRIST, WATCH_OFF_WRIST, DISCONNECTED, FALLBACK_SOUND_ON. Снимок исходной громкости и ringer mode сохраняется до первого изменения звука. Повторные heartbeat не перезаписывают снимок. При снятии доступны максимум, восстановление и пользовательский уровень. При аварийной потере связи используется максимум. При отключении автоматизации восстанавливается исходный режим, если приложение ещё управляет звуком.

FGS экземпляры имеют owner token: отложенный cleanup старого сервиса не останавливает уже перезапущенный мониторинг. На телефоне inexact fallback alarm сохраняется при неожиданном завершении сервиса. После отказа OEM в регистрации off-body датчика Wear UI объясняет и запрашивает соответствующее разрешение; чтение медицинских показателей не включается.

AudioManager читает текущие значения перед записью; ошибки и отсутствие DND policy access отражаются в UI и журнале. Приложение не изменяет глобальный фильтр Do Not Disturb. Доставку сторонних звонков/уведомлений на часы обеспечивает штатное приложение-компаньон; включение вибрации часов настраивается отдельно.

В 1.2.3 звук часов обслуживал WatchSoundController с отдельными интерфейсами устройства и хранилища. WatchRepository сериализует его вызовы своим mutex. Переходы через SILENT проверяют Notification Policy Access до приобретения владения. Снимок сохраняется перед записью в AudioManager для восстановления после гибели процесса; если вызов отклонён и значения не изменились, новое владение удаляется. Частично применённый звук сохраняет снимок. Restore пропускает уже применённые значения, выставляет громкость перед окончательным ringer mode и проверяет результат; отказ сохраняет снимок для следующей попытки.

WatchSoundProblem передаётся отдельным StateFlow в WatchViewModel. Ошибка звука не заменяет состояние датчика или Data Layer и не мешает publish после подтверждения ношения. Исключение системы остаётся диагностикой в журнале, главная страница показывает локализованную подсказку. Refresh UI и ACTION_NOTIFICATION_POLICY_ACCESS_GRANTED_CHANGED повторяют применение/восстановление. Activity наблюдает этот broadcast только пока видима; foreground service обрабатывает его в фоне. Страница «Доступ к звуку» проверяет isNotificationPolicyAccessGranted и предоставляет системный переход или ручную инструкцию ADB. Нового polling/AccessibilityService нет.

## Фон и энергия

В 1.2.0 Wear MonitorRecovery сохраняет отдельный inexact allow-while-idle alarm на 15 минут, который проверяет enabled до действия, сначала планирует следующую проверку, затем запускает FGS с RECHECK_SENSOR. При disable alarm отменяется; на boot учитывается startOnBoot, при обновлении APK восстанавливается включённый мониторинг. Фоновый старт может быть отклонён Android, поэтому UI объясняет REQUEST_IGNORE_BATTERY_OPTIMIZATIONS и открывает системный запрос. Exact alarms для watchdog не применяются. Пользовательская принудительная остановка и задержки OEM остаются ограничениями.

recoveringSubscription повторяет подписку через 30 секунд после upstream error или completion. Cancellation и ошибки downstream не перехватываются; finally закрывает CPU lease попытки доставки. Ошибка подписки не снимает enabled. SCREEN_ON / USER_PRESENT после пяти минут обновляют подписку; резервная проверка тоже обновляет её, чтобы восстановить потерянные OEM callbacks. START_STICKY остаётся первым уровнем восстановления. Доверенный локальный WearableListenerService запрос удерживает CPU только на время приёма/ответа и пытается восстановить службу без Activity.

PhoneLossPopup создаёт TYPE_APPLICATION_OVERLAY на главном Looper после проверки canDrawOverlays. Нативные View не требуют отдельной Activity или AccessibilityService; окно удаляется по кнопке, reconnect, stop или таймауту 30 s. Без разрешения показывается обычное уведомление. Окно не обходит Keyguard. Оригинальный WAV находится в res/raw и воспроизводится MediaPlayer с media volume и transient audio focus; TTS выбирает русский офлайн-голос. CPU lease ограничен и закрывается после окончания/ошибки/отмены. Отсчёт подтверждения потери удерживает CPU кратко; повторные API ошибки не продолжают удержание бесконечно.

В 1.2.1 все Wear UI переходы OVERLAY открывают внутреннюю страницу справки, а не ACTION_MANAGE_OVERLAY_PERMISSION. Samsung может разрешать наложение после ручной команды AppOps и при этом предоставлять системную Activity-заглушку «Недоступно». Единственный источник статуса — Settings.canDrawOverlays; наличие системной Activity не считается признаком доступа. MainActivity наблюдает OPSTR_SYSTEM_ALERT_WINDOW только для собственного пакета между onStart/onStop, повторяет чтение на onResume и по кнопке. Проверка окна повторно читает разрешение в момент нажатия: при отказе открывается справка. Пользователь получает адресованную часам команду ADB; приложение не изменяет AppOps самостоятельно.

В 1.2.2 PhoneLossAlertView использует фотографический фон, bitmap shader с center crop, scrim и статичную рамку. Заголовки и кнопка — нативные текстовые View; размеры привязаны к короткой стороне дисплея, кнопка не меньше 48 dp. ScrollView сохраняет доступность при крупном шрифте. BitmapFactory читает bounds и выбирает sample на IO, не декодирует фотографию при каждом кадре. PhoneLossPopup отменяет Job подготовки и повышает revision при hide/remove; перед mount проверяет актуальность revision и разрешение, поэтому завершившаяся старая загрузка не возвращает закрытое окно. CPU lease на 10 секунд захватывается до начала подготовки и закрывается invokeOnCompletion даже при отмене до запуска coroutine. Время отображения 30 секунд отсчитывается после успешного addView.

Три настройки оповещения передаются с часов через /alert_settings, телефон проверяет capability / isNearby и выбранный node, сохраняет их, отправляет /alert_settings_ack. Часы очищают persistent pending только при совпадении подтверждённых значений. До ACK телефонный CONFIG не перезаписывает локальный выбор; при reconnect и heartbeat pending отправляется повторно. Формат WatchConfig v2 сохранён.

Wear UI использует TransformingLazyColumn и Material 3 scaffolds. Settings/info имеют distinctUntilChanged; журнал разбирается на IO и собирается только в диагностике. Запрос 60 Hz не является подтверждением FPS. Release сборка использует R8/resource shrinking и локальный debug signing certificate для совместимости существующих установок; публичному выпуску нужен отдельный сохранённый release key.

Play services находит `@array/android_wear_capabilities` по имени вне графа ссылок приложения. В обоих модулях `res/raw/dev_dx_wristsound_*_keep.xml` сохраняет этот массив через tools:keep. tools:ignore="UnusedResources" подавляет только Lint и не заменяет правило сохранения. После assembleRelease build-local проверяет aapt2 dump resources готового APK: должен существовать массив и соответствующее значение dx_wrist_phone / dx_wrist_watch. Это защищает контракт обнаружения peer от resource shrinking. [Правила сохранения ресурсов](https://developer.android.com/studio/write/tool-attributes#toolskeep).

Подписка на датчик должна переживать закрытие Activity: только при включённом мониторинге работает FGS `specialUse` с объяснённым subtype. На телефоне FGS `connectedDevice` нужен только при включённой автоматизации для отсчёта короткого disconnect timeout. Оба имеют видимое уведомление и действие остановки. BOOT_COMPLETED восстанавливает их только при включённом автозапуске.

Используются callback и одноразовые coroutine timers. Постоянных wake locks и частого polling нет; краткое удержание CPU существует только на переходе off-body, до завершения debounce и доставки, максимум 75 s. AlarmManager с inexact allow-while-idle служит резервом, если процесс телефона исчезнет. Android Doze/OEM могут задерживать heartbeat и alarm: абсолютная гарантия 15 секунд при suspend невозможна без более затратных механизмов. Эти границы видны в README.

## Проверка

Модульные тесты покрывают debounce, дубли, порядок сообщений, UNKNOWN, восстановление громкости и fallback. Сборка APK и Android Lint проверяют интеграцию. Реальная точность датчика, фоновые ограничения конкретных часов и маршрутизация звонков проверяются на физической паре устройств по процедуре README.

С 1.2.4 AppSettings по умолчанию задаёт VIBRATE для телефона на руке и MAXIMUM после снятия. DataStore SoundProfileMigration (sound_profile_version=1) один раз обновляет эти два режима и отключает watch_vibration до первой выдачи настроек. Состояние активации, paired node, alert settings и сохранённый снимок для cleanup остаются на месте. После этой миграции ручные настройки телефона не перезаписываются.

Автоматическое управление ringer mode часов удалено: confirmed и CONFIG_PATH больше не вызывают аудиопереключение. При чтении/записи watchVibration=false; поле WatchConfig.vibration сохранено в wire format, отправляется false и игнорируется на часах. Старый телефон не может снова включить принудительную вибрацию новых часов.

WatchSoundController теперь выполняет только releaseLegacyVibration при begin/refresh/stop. При отсутствии собственного снимка не пишет в AudioManager. Если пользователь уже вышел из VIBRATE, удаляет старый снимок без вмешательства в громкость. Если старый снимок не описывает слышимый NORMAL, удаляет его без применения. Иначе один раз восстанавливает громкость и NORMAL; при отказе сохраняет попытку для ручного восстановления/повтора. Метод vibrate удалён; единственный записываемый режим часов — NORMAL для завершения старого изменения. После cleanup новое владение не приобретается. Повторные подтверждения датчика, CONFIG, heartbeat, stop/start и выбор мелодии не возвращают VIBRATE.
